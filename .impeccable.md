# Impeccable Design Context — War of Names (حرب الأسماء)

## Design Context

### Users

**Primary: Participants (متسابقين)**
Arabic-speaking young adults (likely 18-35) who join closed, seasonal alias-based competitions. They interact via mobile-first interfaces under anonymous aliases, attacking other players by guessing real identities, answering quiz questions, buying items from an in-game store, and tracking their rank on leaderboards. Their context is social, competitive, and strategic — they're playing a game of deduction and resource management among friends or community members.

**Secondary: Admins (مشرفين)**
Competition organizers who create and manage all aspects of the platform — seasons, cycles, questions, items, distributions, and player states. They need a powerful, organized control panel that feels part of the same product but is calmer and more information-dense. Optimized for tablet/desktop.

**Job to be done:** Compete under an alias, guess identities, earn points, climb rankings, and have fun in a structured seasonal format — all managed effortlessly by an admin.

### Brand Personality

**Three words:** Competitive, Smart, Vibrant

**Voice & Tone:**
- Arabic-first, youthful but not childish
- Labels are clear standard Arabic; interactive messages/feedback can have controlled personality (e.g., "ضبطتها!" for successful attack)
- Admin-facing copy is more direct and less playful, but still within the brand family
- Never corporate, never overly casual/slangy, never boring

**Emotional goals by context:**
- **Attacks & battles:** Anticipation, excitement, suspense
- **Dashboard & stats:** Confidence, control, strategic clarity
- **Store, rewards, reveals:** Delight, discovery, surprise
- **Admin panel:** Trust, reliability, efficiency

### Aesthetic Direction

**Visual tone:** Professional clean + elegant competitive game + strategic mystery touch. "Game-lite controlled" — not a full game HUD, not a corporate dashboard. A smart hybrid.

**What it should feel like:**
- Youthful, vibrant, smart, clean
- Colorful but calculated — never a rainbow
- Has personality and energy
- Memorable identity

**What it must NOT look like:**
- Corporate admin dashboard (cold, lifeless)
- Children's game (cartoon, loud)
- Neon/gamer RGB aesthetic (aggressive)
- Cheap template or generic UI kit
- Glassmorphism, heavy gradients, or realism
- Disconnected pages with different visual spirits

**Primary reference:** حروف مع عزيز (Arabic game app) — for its clean Arabic identity, bold titles, youthful interaction style, and balanced layout. Not copied, but used as directional inspiration for cleanliness, contrast, and Arabic-native design.

**Theme:** Both light and dark mode. Light mode uses #F8F9FA background; dark mode uses #111827 background. Both must feel equally polished and intentional.

**Shape Language:**
- Hexagons as signature motif
- Rounded pills for controls/buttons
- Framed cards with rounded corners (rounded-2xl / rounded-3xl)
- Strong outlines on interactive elements
- Controlled layered shadows (shadow-sm to shadow-md)
- Chamfered clip-path cards for special elements

**Surface Style:**
- Flat-ish base with outlined borders
- Light layered shadows (not heavy drop shadows)
- No glassmorphism, no heavy gradients as base treatment
- Gradients allowed sparingly for CTAs and rank badges

**Border Radius Scale:**
- Buttons: rounded-xl (12px)
- Cards: rounded-2xl (16px) to rounded-3xl (24px)
- Badges: rounded-md (6px) to rounded-lg (8px)
- Inputs: rounded-xl (12px)
- Avatar/rank badges: rounded-xl (12px)

**Elevation:**
- Default cards: shadow-sm with border
- Hover cards: shadow-md with -translate-y-1
- Dark mode: shadow-none or shadow-black/20
- No mixed shadow styles — consistent across all card types

**Motion Direction:**
- Transitions: 0.2s cubic-bezier(0.4, 0, 0.2, 1) ("smooth-transition")
- Button press: scale(0.98) translateY(2px)
- Page transitions: CSS View Transitions API (fade-out/fade-in with translateY)
- Hover: -translate-y-0.5 to -translate-y-1
- Allowed moments: soft pop, lift/fade, slide with intent, reveal, burst light, controlled confetti, box opening reveal
- Forbidden: slow transitions, excessive effects, multiple simultaneous animations, cheap mobile game effects

### Layout & Navigation

**Direction:** RTL (right-to-left) — every layout decision must account for this.

**Responsive strategy:** Mobile-first for participants, tablet/desktop optimized for admin.

**Participant navigation:**
- Desktop: Top horizontal nav (الرئيسية, المتصدرين, المتجر, قواعد اللعبة)
- Mobile: Fixed bottom nav with 5 items (home, leaderboard, attack FAB, store, profile)
- Attack button is elevated FAB in center of bottom nav

**Admin navigation:**
- Sidebar + top utility bar
- Information-dense but clean

**Shared elements with view-transition-name:**
- main-header / main-nav: persists across navigations (no animation)
- mobile-nav: persists across navigations (no animation)
- main-content: fades out/in with slight translateY

### Design Principles

1. **Unity over variety** — Every page, card, modal, and list comes from the same visual family. No "each page has its own style" chaos. Shared shells, shared patterns, shared tokens.

2. **Game energy, platform discipline** — Participant-facing screens get more visual accents, vibrant cards, and clear feedback. Admin-facing screens are calmer, denser, and more organized. But both share the same design DNA.

3. **Clarity is king** — Excellent hierarchy, fast scanning, no ambiguity. Labels are clear, states are obvious, actions are unmistakable. The interface never needs a manual.

4. **Controlled personality** — The interface has character (bold titles, playful microcopy, animated moments) but never at the expense of usability. Fun is calculated, not chaotic.

5. **Arabic-native, not translated** — Typography, layout, spacing, and reading flow are designed for Arabic RTL from the ground up, not adapted from an LTR template.

### Accessibility

- **Target:** WCAG AA compliance
- Sufficient color contrast ratios for all text/background combinations
- Keyboard navigation support
- Screen reader compatible semantic markup
- Clear focus indicators
- Readable font sizes (minimum 14px body text on mobile)
- Reduced motion: not a formal requirement currently, but nice-to-have

### Special Screens

**Lobby (09-lobby-linked.html):** Fully dark-only immersive screen. Uses backdrop-blur, hexagon SVG background patterns, rotating shapes, magnetic hover effects (JS-driven), and spring/smooth custom easing curves. No standard header/footer/mobile-nav. Each button is color-coded (teal=profile, purple=leaderboard, orange=store, blue=rules) and arranged in an arc layout on desktop.
